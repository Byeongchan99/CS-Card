요약 노트는 공부 세션과 **분리된 트랙**이다. 카드와 연결하지 않으며, 카드가 없는 주제도
자유롭게 담는 독립 콘텐츠다. 퀴즈를 돌리고 만든 복습 노트를 분야별 페이지에 병합한다.

붙여넣은 복습 노트: $ARGUMENTS

## 1. 분류

붙여넣은 노트를 8개 대분류로 나눈다 — 알고리즘, 자료구조, 운영체제, 유니티, C#,
디자인 패턴, 게임 수학·물리, 그래픽스. 대상 파일은 `summary-notes/` 아래에 있다
(`C샵.md`, `게임-수학-물리.md`, `디자인-패턴.md` 처럼 파일명 규칙이 적용돼 있다).

원본 노트가 자체 분류(예: "디자인 패턴 & SOLID")를 쓰더라도 위 8개로 매핑한다.

## 2. 항목 단위 병합

기존 페이지의 `##` 항목과 붙여넣은 항목을 **주제 단위로 대조**한다.

- **같은 주제면 한 항목으로 통합한다.** 가장 정확한 서술을 바탕으로 쓰고, 다른 쪽에만
  있는 정보를 흡수한다. 같은 내용을 두 항목으로 남기지 않는다.
- **새 주제면 관련 항목 옆에 배치한다.** 페이지는 평평한 `##` 구조를 유지하되(그룹 헤딩을
  넣지 않는다) 배열 순서를 주제별로 인접하게 잡아, 목차가 길어도 흐름으로 읽히게 한다.
- 항목이 다른 분야에 더 맞으면 옮기고 그 사실을 보고한다.

## 3. 형식

- 항목마다 `##` 헤딩 + 2~4문장 요약
- 헷갈렸던 지점은 `> [!tip] 복습 포인트` 콜아웃으로 분리
- A vs B 형태의 비교는 표로
- 종결어미를 생략한 간결체 (심화 노트의 `~다` 문체와 다르다)
- 세션 부기는 넣지 않는다 — `====` 구분선, 번호 매김, "N일차 학습", "퀴즈 N~N번",
  "새 개념 —" 같은 접두사

## 4. 손대지 않는 것

기술 서술은 바꾸지 않는다. 읽기 구조(헤딩·표·콜아웃)와 중복 통합만 다룬다.
병합하다 사실이 어긋나는 걸 발견하면 **고치지 말고 목록으로 보고한다.**

요약 노트에는 카드 `[[위키링크]]`를 넣지 않는다. 카드와 연결하지 않는 것이 원칙이다.

## 5. 검증 후 커밋

- 세션 부기 잔존 0건인지 grep (`====`, `일차`, `퀴즈 \d+`)
- 콜아웃이 `> [!tip] 복습 포인트` + `>` 본문 줄 형태인지
- 파일명에 금지 문자가 없는지

변경 요약(분야별 항목 수 변화, 통합한 항목, 발견한 문제)을 먼저 보여준 뒤 커밋·푸시하고
GitHub Actions 결과를 확인한다.
