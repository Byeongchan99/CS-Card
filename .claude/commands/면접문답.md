description: 대분류를 받아 요약 노트 기반 면접 문답 페이지(content/<slug>-interview.md)를 생성한다
argument-hint: 대분류 이름 (선택: 문항 수·다룰 주제)
---

분야별 "면접 대비 문답" 페이지를 만든다. 해당 분야의 **요약 노트를 토대로** 예상 질문·모범
답변·꼬리질문을 정리하고, 체크리스트로 진행을 관리하는 인터랙티브 페이지다. 첫 사례는
운영체제(`content/os-interview.md`). 모든 분야 페이지는 공유 스크립트 `content/interview.js`
하나를 참조한다(CSS 주입·체크리스트·툴바가 그 안에 있으니 분야별 JS를 새로 만들지 않는다).

입력: $ARGUMENTS

## 1. 대상 분야 확정

입력에서 대분류를 고른다 — 알고리즘, 자료구조, 운영체제, 유니티, C#, 디자인 패턴,
게임 수학·물리, 그래픽스. 소스는 `summary-notes/<분야>.md`(파일명 규칙: `C#`→`C샵`,
`게임 수학·물리`→`게임-수학-물리`, `디자인 패턴`→`디자인-패턴`).

출력 파일은 `content/<slug>-interview.md`. slug는 URL·파일명 금지문자를 피한 영문:

| 대분류 | slug | 대분류 | slug |
| --- | --- | --- | --- |
| 운영체제 | os | C# | csharp |
| 자료구조 | ds | 유니티 | unity |
| 알고리즘 | algo | 그래픽스 | graphics |
| 디자인 패턴 | design-patterns | 게임 수학·물리 | math-physics |

이미 그 분야 페이지가 있으면 새로 만들지 말고 기존 파일에 문항을 덧붙이거나 갱신한다.

## 2. 문항 뽑기

`summary-notes/<분야>.md`를 읽고, 노트의 주제 묶음을 그대로 그룹으로 삼아 문항을 만든다.
그룹당 4~6문항, 페이지 전체 20~30문항이 기준(입력에 문항 수가 있으면 따른다). 각 문항은:

- **질문** — 실제 면접에서 나올 법한 형태로. 한 문항 = 한 질문.
- **핵심 답변** — 결론 한 문장 먼저 → 이유 → 트레이드오프. 노트의 깊이를 반영하되 말로 30~60초.
- **꼬리질문** — 그 답을 파고드는 예상 후속 1~3개와 모범 대응. 세션에서 실제로 헷갈렸던
  지점(예: TLB 미스 vs 페이지 폴트, 비동기≠병렬)이 좋은 꼬리질문 소재다.
- **함정**(선택) — 자주 틀리거나 단정하면 감점되는 지점이 있을 때만.

답변 스타일: 단정("절대 안 됩니다") 금지 → "일반적으로 ~지만 ~한 경우엔 다릅니다". 오버하는
비유 금지, 담백하되 실질 내용은 충분히.

## 3. 페이지 형식 (raw HTML + 공유 스크립트)

프론트매터 `title`만 두고, 짧은 안내문 뒤에 `<div class="osiv"> … </div>`를 쓰고 마지막에
`<script src="./interview.js"></script>`를 둔다. 구조와 클래스는 `content/os-interview.md`를
본보기로 그대로 따른다.

- **`.osiv` 안에는 빈 줄을 넣지 않는다** — Quartz raw HTML 블록이 빈 줄에서 쪼개져 깨진다.
  일반 줄바꿈은 괜찮다.
- `.note`(답변 프레임 안내) → `.bar`(진행률 `#osiv-done`/`#osiv-total`, 버튼
  `osiv-open`/`osiv-hide`/`osiv-reset`) → `section.grp`(그룹: `.grp-head`에 `h3`+`.cnt`,
  `.grp-note`) → `.q`(체크박스 + `<details>`) 순.
- 각 `.q`: `<label class="chk"><input type="checkbox" id="qN">`(id는 페이지 전체에서 q1부터
  순번, aria-label "N번 자신 있음") + `<details>`(summary에 `.qtag` 태그·`.qtext` 질문·chev
  SVG, `.ans`에 `.core`(핵심 답변)·`.tails`(꼬리질문 `<q>…</q>` + 답)·`.trap`(함정)).
- 그룹 헤더의 `.cnt`(N문항)와 진행률 `#osiv-total`은 실제 문항 수와 맞춘다(total은 스크립트가
  체크박스 수로 자동 채우지만 텍스트도 맞춰둔다).
- CSS·JS를 인라인 `<style>`/`<script>`로 넣지 않는다(Quartz가 내용을 이스케이프한다). 스타일이나
  동작을 바꿔야 하면 공유 `content/interview.js`만 수정한다 — 전 분야에 반영된다.
- HTML 특수문자는 이스케이프: 제네릭·비교는 `List&lt;T&gt;`, `A &gt; B`, `&amp;`.

끝나면 홈 `content/index.md`의 링크 목록에 한 줄 추가한다(예:
`- [🎤 <분야> 면접 문답](./<slug>-interview) — …`).

## 4. 검증 후 커밋

- `.osiv` 블록 안 빈 줄 0건, `<script src="./interview.js">` 존재
- 체크박스 id가 q1..qN 연속, `.cnt` 합과 문항 수 일치
- 파일명 금지문자 없음(`#`, `.`, `/`, `:` 등)

변경 요약(분야, 그룹·문항 수)을 먼저 보여준 뒤 커밋·푸시한다. 로컬에 Node가 없으므로 빌드는
GitHub Actions로만 확인된다 — curl로 Actions 상태를 폴링해 success를 확인하고, 배포되면
`https://byeongchan99.github.io/CS-Card/<slug>-interview`를 열어 렌더·체크리스트·다크모드를 본다.
