"면접 대비 문답"은 **모든 분야가 한 페이지(`content/interview.md`)에 모여** 상단 탭으로 전환되는
통합 페이지다. 해당 분야의 **요약 노트를 토대로** 예상 질문·모범 답변·꼬리질문을 정리하고,
체크리스트로 진행을 관리한다. 이 커맨드는 새 분야면 그 페이지에 `<div class="field" data-field="<slug>">`
블록과 탭 버튼을 **추가**하고, 이미 있는 분야면 그 `.field` 블록만 **교체**한다. 새 페이지를 만들지 않는다.
CSS 주입·체크리스트·툴바·탭 전환은 공유 스크립트 `content/interview.js` 하나에 있으니 JS를 새로 만들지 않는다.

입력: $ARGUMENTS

## 1. 대상 분야 확정

입력에서 대분류를 고른다 — 알고리즘, 자료구조, 운영체제, 유니티, C#, 디자인 패턴,
게임 수학·물리, 그래픽스. 소스는 `summary-notes/<분야>.md`(파일명 규칙: `C#`→`C샵`,
`게임 수학·물리`→`게임-수학-물리`, `디자인 패턴`→`디자인-패턴`).

출력은 `content/interview.md` 안의 그 분야 `.field` 블록이다. 분야 식별자 slug(`data-field` 값,
체크박스 id 접두, 저장 키에 쓰임):

| 대분류 | slug | 대분류 | slug |
| --- | --- | --- | --- |
| 운영체제 | os | C# | csharp |
| 자료구조 | ds | 유니티 | unity |
| 알고리즘 | algo | 그래픽스 | graphics |
| 디자인 패턴 | design-patterns | 게임 수학·물리 | math-physics |

`content/interview.md`에 그 `data-field` 블록이 이미 있으면 그 `.field`만 교체하고, 없으면
`.tabs`에 탭 버튼 한 개(순서는 위 표대로: algo·ds·os·unity·csharp·design-patterns·math-physics·graphics)와
`.field` 블록을 새로 끼운다. 첫 분야가 아니면 `.field`에 `hidden` 속성을 단다(활성 탭만 노출).

## 2. 문항 뽑기

`summary-notes/<분야>.md`를 읽고, 노트의 주제 묶음을 그대로 그룹으로 삼아 문항을 만든다.
그룹당 4~6문항, 페이지 전체 20~30문항이 기준(입력에 문항 수가 있으면 따른다). 각 문항은:

- **질문** — 실제 면접에서 나올 법한 형태로. **한 문항은 한 가지만 묻는다.** "왜 필요하고 어떻게
  동작하나요?", "A는 무엇이고 B는 어떻게 다른가요?"처럼 여러 개를 한 질문에 묶지 않는다. 두 번째로
  묻고 싶은 것은 (가) 그 답을 파고드는 성격이면 **꼬리질문**으로 빼고, (나) 독립된 주제면 **별도
  문항**으로 나눈다. 예: "페이지 폴트가 나면? 스래싱은?"은 두 문항으로, "동기/비동기와 블로킹/논블로킹
  차이는? 비동기는 병렬?"은 앞을 본문항·뒤를 꼬리질문으로.
- **핵심 답변** — 아래 프레임 순서를 지킨다: ① 정의/결론 한 문장 먼저 → ② 왜 그렇게
  동작·설계됐는지 → ③ 트레이드오프 → ④ 필요하면 실제·실무 예시 한 줄. 노트의 깊이를 반영하되
  말로 30~60초 분량.
- **꼬리질문** — 그 답을 파고드는 예상 후속 1~3개와 모범 대응. 세션에서 실제로 헷갈렸던
  지점(예: TLB 미스 vs 페이지 폴트, 비동기≠병렬)이 좋은 꼬리질문 소재다.
- **함정**(선택) — 자주 틀리거나 단정하면 감점되는 지점이 있을 때만.

**주제형과 상황형을 섞는다.** 주제형("A는 무엇인가요?", "A와 B는 어떻게 다른가요?")만 있으면
암기처럼 보인다. 그룹들 뒤에 **"상황형 문제 해결"** 그룹(4~5문항)을 두어, 실무 상황을 던지고
CS로 풀게 한다.

- **상황형 문항** — "게임이 오래 켤수록 느려집니다", "CPU는 한가한데 순회가 느립니다"처럼 증상·시나리오로
  묻는다. 한 상황에 2~3개 영역(성능·GC·자료구조·동기화·캐시 등)이 얽히게 만드는 게 포인트. 답변은
  "먼저 무엇으로 원인을 좁힐지(측정)" 태도를 앞에 두고, 그다음 얽힌 CS 개념으로 설명한다.
- **실무 + CS를 엮는 꼬리질문 패턴** — 주제형·상황형 어디든 이런 각도의 꼬리질문이 좋다.
  규모나 호출 빈도가 100배가 되면 어떻게 되는가(성능·GC), 기존 코드를 실제로 어떻게 바꾸는가
  (마이그레이션), 왜 다른 방법은 안 되는가(대안 비교).

**답변 문체 — 소리 내어 읽으면 그대로 면접 답변이 되게 쓴다.** 이건 공부용 페이지라 스캔되는
구조는 살리되, 말로 하지 않는 표기는 쓰지 않는다.

- **말하는 완결 문장**으로 쓴다. 화살표(`→`), 가운뎃점 나열(`레지스터·PC·SP`), 문장 연결용
  em대시(`A — B`)는 실제로 입으로 말하지 않으므로 금지. 순서는 "먼저 ~하고, 그다음 ~합니다"처럼
  풀어 쓴다.
- **기호는 말로 푼다.** `2⁵²` → "2의 52제곱", `H > M > L` → "높은·중간·낮은 우선순위 스레드",
  `≠` → "~가 아니다". `O(n)` 같은 건 그대로 두기보다 "대상 수에 비례해 느려진다"처럼 풀어 쓰면
  더 자연스럽다. 코드 식별자(`count++`, `fork`, `wait`, `epoll`)는 `<code>`로 그대로 둔다.
- **읽기 좋은 구조는 유지.** 리드 문장은 `<strong>`으로 감싸 결론이 눈에 띄게 하고, 열거되는
  항목은 불릿으로 두되 각 항목을 "**굵은 키워드.** 말하는 문장." 형태로 쓴다(`—` 조각 금지).
- 단정("절대 안 됩니다") 금지 — "일반적으로 ~지만 ~한 경우엔 다릅니다". 오버하는 비유 금지,
  담백하되 실질 내용은 충분히.

## 3. 분야 블록 형식 (raw HTML + 공유 스크립트)

`content/interview.md`의 `<div class="osiv"> … </div>` 안은 `.tabs`(탭 버튼들) 다음에 분야마다
`<div class="field" data-field="<slug>"> … </div>` 블록이 이어지는 구조다. 새 분야는 이 두 곳에
끼운다. 한 분야 `.field` 블록의 내부 구조(기존 블록을 본보기로 그대로 따른다):

- `.note`(답변 프레임 안내) → `.bar`(진행률 `.prog-done`/`.prog-total`, 버튼
  `.tool-open`/`.tool-hide`/`.tool-reset`) → `section.grp`(그룹: `.grp-head`에 `h3`+`.cnt`,
  `.grp-note`) → `.q`(체크박스 + `<details>`) 순. **id가 아니라 class 기반**이다(진행률·툴바
  id는 한 페이지에 여러 분야가 있어 겹치므로 쓰지 않는다).
- 각 `.q`: `<label class="chk"><input type="checkbox" id="<slug>-qN">`(**id는 분야 slug로 접두**,
  분야 안에서 q1부터 순번, aria-label "N번 자신 있음") + `<details>`(summary에 `.qtag` 태그·
  `.qtext` 질문·chev SVG, `.ans`에 `.core`(핵심 답변)·`.tails`(꼬리질문 `<q>…</q>` + 답)·`.trap`(함정)).
- `.bar`는 이렇게 쓴다(진행률 텍스트만 문항 수에 맞춘다. total은 스크립트가 자동 채우지만 맞춰둔다):
  `<div class="bar"><span class="prog"><b class="prog-done">0</b> / <span class="prog-total">N</span> 자신 있음</span><span class="bar-sp"></span><button class="tool tool-open" type="button">모두 펼치기</button><button class="tool tool-hide" type="button" aria-pressed="false">체크 숨기기</button><button class="tool tool-reset" type="button">초기화</button></div>
- 탭 버튼: `.tabs` 안에 `<button class="tab" type="button" role="tab" data-field="<slug>" aria-selected="false"><대분류></button>`
  를 위 slug 표 순서에 맞는 자리에 넣는다(활성 탭 하나만 `aria-selected="true"`).
- **`.osiv` 안에는 빈 줄을 넣지 않는다** — Quartz raw HTML 블록이 빈 줄에서 쪼개져 깨진다.
  일반 줄바꿈은 괜찮다.
- CSS·JS를 인라인 `<style>`/`<script>`로 넣지 않는다(Quartz가 내용을 이스케이프한다). 스타일이나
  동작을 바꿔야 하면 공유 `content/interview.js`만 수정한다 — 전 분야에 반영된다.
- HTML 특수문자는 이스케이프: 제네릭·비교는 `List&lt;T&gt;`, `A &gt; B`, `&amp;`.

홈 `content/index.md`에는 통합 링크(`- [🎤 면접 문답](./interview) — …`)가 이미 있으므로 건드리지 않는다.

## 4. 검증 후 커밋

- `.osiv` 블록 안 빈 줄 0건, 페이지 끝에 `<script src="./interview.js">` 존재
- 새/갱신 분야의 체크박스 id가 `<slug>-q1..<slug>-qN` 연속(다른 분야 id와 겹치지 않음), `.cnt` 합과 문항 수 일치
- 그 분야 `.field`에 대응하는 `.tabs` 탭 버튼이 정확히 1개, `data-field`가 서로 일치
- `.bar`가 class 기반(`prog-done`/`prog-total`/`tool-open`/`tool-hide`/`tool-reset`), id 기반 `osiv-*` 잔재 없음

변경 요약(분야, 그룹·문항 수)을 먼저 보여준 뒤 커밋·푸시한다. 로컬에 Node가 없으므로 빌드는
GitHub Actions로만 확인된다 — curl로 Actions 상태를 폴링해 success를 확인하고, 배포되면
`https://byeongchan99.github.io/CS-Card/interview`를 열어 해당 탭의 렌더·체크리스트·다크모드를 본다.
