## 질문
`MoveCommand`의 `Undo()`를 "저장해둔 방향의 반대로 같은 거리만큼 이동"으로 구현했다. 이 역연산 구현이 틀린 결과를 내는 상황은 무엇이고, 그 대신 커맨드는 무엇을 들고 있어야 하는가?

## 핵심 답변
실행 이후 외부 요인이 위치를 바꾸면 현재 위치에 역벡터를 더한 결과는 실행 전 위치가 아니다. 외부 개입이 없어도 벽 충돌로 이동이 도중에 막혔다면 실제 변위가 명령한 거리보다 작아 원래보다 뒤로 밀려난다. 근본 원인은 역연산이 "명령한 값 = 실제로 일어난 결과"를 가정한다는 점이다. 그래서 역연산이 아니라 실행 전 상태 자체를 스냅샷으로 저장하고 undo에서 그 값을 대입해야 한다.

## 정리

### 왜 그런가
역연산 방식은 상태 변화가 수학적으로 가역이고 그 사이 누구도 대상을 건드리지 않는다는 두 가정에 의존한다. 게임 로직에서는 클램프, 충돌, 상한선, 물리 개입, 반올림 때문에 이 가정이 자주 깨진다.

```csharp
// 역연산 — 실행 직후 undo에서만 안전하다
public void Undo() => _target.position -= _direction * _distance;

// 스냅샷 — 무엇이 끼어들었든 원래 값으로 돌아간다
public void Undo() => _target.position = _previousPosition;
```

### 트레이드오프
스냅샷은 상태 크기만큼 메모리를 더 쓴다. 역연산은 메모리를 거의 쓰지 않지만 오차가 누적되어 undo를 여러 번 했을 때 상태가 서서히 어긋나는 형태로 드러난다. 카운터 증감처럼 확실히 가역이고 대상이 그 커맨드로만 변하는 좁은 경우에만 역연산을 쓴다.

### 흔한 오해/함정
"이동의 반대는 반대 방향 이동"이라는 직관이 문제다. 커맨드가 기록해야 하는 것은 자기가 지시한 변화량이 아니라 변화 이전의 실제 상태다.
