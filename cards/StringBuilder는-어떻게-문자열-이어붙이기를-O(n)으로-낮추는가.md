## 질문
`string += ` 루프는 이어붙이기가 O(n²)다. `StringBuilder`는 확장할 때 여전히 "기존 문자 전체 복사"가 일어나는데도 전체 비용이 O(n²)가 되지 않는다. 왜 O(n)인가? 동적 배열의 상환 분석 논리로 설명하라.

## 핵심 답변
`StringBuilder`는 불변 객체를 매번 새로 만드는 대신 변경 가능한 내부 버퍼(`char[]`)를 들고, `Append`는 버퍼 빈 자리에 문자를 채운다. 버퍼가 꽉 찰 때만 대략 2배로 확장하며 기존 문자를 복사한다 — `List`의 배열 증가와 같은 메커니즘이다. `string += `와의 차이는 복사 빈도다. `string`은 매 반복 전체 복사가 강제되어 1+2+...+n = O(n²)이지만, StringBuilder는 2배가 될 때만 복사해 1+2+4+...+n = O(n)이다. 복사가 등차수열이 아니라 등비수열로 쌓이므로 상환하면 Append당 O(1), 전체 O(n)이다.

## 정리

### 왜 그런가
같은 "복사"라도 언제 하느냐가 복잡도를 바꾼다. 불변인 `string`은 선택지가 없어 매번 복사한다. StringBuilder는 가변 버퍼 덕에 버퍼가 꽉 찰 때만 복사하고, 그 간격이 기하급수적으로 벌어진다. 복사 빈도가 산술적이냐 기하급수적이냐가 등차수열 합과 등비수열 합의 차이, 즉 O(n²)와 O(n)의 차이로 나타난다.

### 내부 동작
```
일반 Append:  n번 × O(1)              = O(n)
확장 시 복사:  1 + 2 + 4 + ... + n     ≈ 2n = O(n)   (등비수열 합)
합계: O(n),  Append당 상환 O(1)
```
비교:
```
string += :      1 + 2 + 3 + ... + n   (매 반복 복사)      = O(n²)
StringBuilder:   1 + 2 + 4 + ... + n   (2배 될 때만 복사)  = O(n)
```

### 실무(게임 개발)에서 생기는 문제와 해결
루프로 문자열을 조립하는 경로에서는 StringBuilder를 쓴다. 최종 길이를 대략 알면 생성자나 `EnsureCapacity`로 초기 용량을 잡아 등비수열 합의 복사마저 없앤다. 반대로 조각 수가 고정이면 문자열 보간(`$"{a}{b}"`)이나 `string.Concat`/`Join`이 필요한 크기를 한 번에 계산해 할당 한 번으로 끝나므로 더 낫다. 판단 기준은 "이어붙이는 횟수가 루프에 의해 커지는가"다.

### 흔한 오해/함정
StringBuilder가 항상 정답은 아니다. 몇 조각을 한 번 합칠 뿐이면 오히려 과하다. 또한 "확장할 때 복사하니 StringBuilder도 복사가 많다"고 오해하기 쉬우나, 복사가 2배 간격으로만 일어나 상환하면 사라진다.
