## 질문
유니티에서 왕복 순찰을 `IEnumerator Patrol()` 안의 `while (true)`와 두 `for`문으로 작성하고, 각 `for`문 안에 `yield return null`을 넣어 `StartCoroutine`으로 실행했다. `while (true)`가 그대로 있는데도 이 코드가 화면을 멈추지 않는 이유는 무엇인가? 그리고 함수가 반환되면 사라지는 두 정보, 지역 변수 `x`와 "지금 어느 `for`문을 실행 중인가"는 각각 어디에 보존되는가?

## 핵심 답변
`yield return`이 매 반복마다 제어권을 유니티에 돌려주므로, 한 번의 호출이 무한 루프를 끝없이 도는 일이 없다. C# 컴파일러는 반복자 메서드를 `IEnumerator`를 구현하는 숨겨진 상태 머신 클래스로 변환한다. 지역 변수 `x`는 그 클래스의 필드로 옮겨지고, 실행 위치는 정수 상태 필드 하나로 기록된다. 업데이트 메서드에서 사람이 손으로 하던 "상태를 필드로 꺼내기"를 컴파일러가 대신 해 주는 것이다.

## 정리
### 내부 동작
```text
IEnumerator Patrol()  ──컴파일──▶  class <Patrol>d__0 : IEnumerator<object>
                                     int  <>1__state;   // 실행 위치
                                     int  <x>5__1;      // 첫 for문의 x
                                     int  <x>5__2;      // 둘째 for문의 x
                                     bool MoveNext();
```

### 흔한 오해/함정
"코루틴은 별도 스레드에서 돈다"는 오해가 흔하다. 코루틴은 메인 스레드에서 실행되며, 실행을 프레임 단위로 잘라 놓은 것뿐이다. `yield` 없이 무거운 작업을 하면 코루틴 안에서도 프레임이 그대로 멈춘다.

### 트레이드오프
`StartCoroutine`마다 반복자 객체가 힙에 할당되고, `new WaitForSeconds(...)`를 매번 만들면 그만큼 GC 대상이 늘어난다.
