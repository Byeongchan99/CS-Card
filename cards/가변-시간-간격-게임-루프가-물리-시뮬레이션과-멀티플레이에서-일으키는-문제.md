## 질문
매 프레임 실제 경과 시간을 `Update(elapsed)`에 넘기는 가변 시간 간격 게임 루프는 프레임레이트와 무관하게 이동 속도를 맞춰 준다. 이 방식이 물리 시뮬레이션과 멀티플레이·리플레이 관점에서 각각 일으키는 문제는 무엇이고, 왜 생기는가?

```csharp
while (running)
{
    double now = GetCurrentTime();
    double elapsed = now - last;
    ProcessInput();
    Update(elapsed);   // position += velocity * elapsed
    Render();
    last = now;
}
```

## 핵심 답변
가변 dt는 평균 속도만 맞출 뿐 시뮬레이션 결과는 맞추지 못한다. 물리 쪽에서는 dt가 커질수록 적분 오차가 커지고, 한 스텝 이동 거리가 늘어 얇은 충돌체를 건너뛰는 터널링이 생긴다. 멀티플레이와 리플레이 쪽에서는 기기마다 dt 수열이 다르다. 수치 적분은 총 시간이 같아도 스텝 크기에 따라 다른 값을 내므로, 같은 입력에서 다른 상태가 나온다. 그래서 시뮬레이션은 고정 dt로 돌리고 렌더링과 분리한다.

## 정리
### 왜 그런가
결과가 갈리는 원인은 "실제 시간을 몇 조각으로 나누어 적분했는가"가 기기마다 다르다는 데 있다. 총 경과 시간이 같다는 사실은 결과가 같다는 것을 보장하지 않는다.

### 흔한 오해/함정
결과 차이를 부동소수점 반올림 문제로만 이해하는 것은 함정이다. 반올림이 전혀 없는 계산에서도 적분 방식 자체의 오차 때문에 결과가 달라진다.
