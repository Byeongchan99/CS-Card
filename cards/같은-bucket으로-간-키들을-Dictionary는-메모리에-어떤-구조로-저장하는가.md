## 질문
같은 bucket으로 떨어진 키가 여러 개(충돌)일 때, .NET Dictionary는 그 충돌한 항목들을 메모리에 어떤 구조로 저장하는가? 노드 객체를 new해서 포인터로 잇는 진짜 연결 리스트를 쓰는가?

## 핵심 답변
노드 객체를 포인터로 잇는 연결 리스트가 아니라, 하나의 배열 안에서 정수 인덱스로 잇는 체인이다. 충돌한 원소들은 논리적으로는 단일 연결 리스트지만, 그 노드가 개별 힙 객체가 아니라 하나의 entries 배열 안 슬롯이고, 포인터 대신 각 슬롯이 가진 정수 인덱스(next)로 다음 원소를 가리킨다.

## 정리

### 왜 그런가
교과서적 해시테이블은 bucket마다 연결 리스트를 달고 충돌 때마다 노드를 new한다. 그러면 원소마다 힙 객체가 하나씩 생겨 메모리 곳곳에 흩어지고, 순회 시 포인터를 따라 캐시 미스가 연발하며, 객체 수만큼 GC가 추적할 대상이 늘어난다.

### 내부 동작
배열 + 정수 인덱스 방식은 반대다. 원소들이 하나의 연속된 배열 안에 모여 있어 체인을 따라가도 같은 배열 안을 오가므로 캐시 지역성이 좋다. 원소를 넣을 때 노드 객체를 따로 할당하지 않으니 GC가 볼 객체도 생기지 않는다.

### 트레이드오프
"충돌은 연결 리스트로 처리한다"는 흔한 설명이 형태상 틀린 건 아니다. 논리 구조는 단일 연결 리스트가 맞다. 차이는 물리적 표현에 있다 — 노드가 흩어진 힙 객체가 아니라 배열 슬롯이고, 링크가 포인터가 아니라 인덱스다.
