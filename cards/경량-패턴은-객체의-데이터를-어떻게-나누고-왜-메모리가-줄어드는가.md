## 질문
나무 10만 그루를 배치하는 게임에서 각 Tree 객체가 메시, 껍질 텍스처, 잎 텍스처, 위치, 회전, 스케일, 색조를 모두 자기 필드로 들고 있다. 경량(Flyweight) 패턴을 적용하면 이 필드들을 어떻게 나누고, 무엇을 기준으로 나누며, 왜 메모리가 줄어드는가?

## 핵심 답변
메시와 텍스처는 나무가 어디에 어떻게 놓였는지와 무관하므로 내재 상태로 묶어 종류당 하나의 공유 객체(TreeType)에 두고, 위치·회전·스케일·색조는 개체마다 달라지므로 외재 상태로 각 Tree에 남긴다. 나누는 기준은 그 값이 배치 맥락에 따라 달라지는가이다. 인스턴스마다 복사되던 내재 상태가 종류 수만큼으로 줄기 때문에 메모리가 준다. 단, 내재 상태가 원래부터 참조로 공유되고 있었다면 절약되는 것은 참조 필드 크기뿐이다.

## 정리
### 개념
경량 패턴은 대량의 객체가 똑같은 데이터를 각자 들고 있을 때, 공유 가능한 부분을 별도 객체로 빼내 여러 인스턴스가 가리키게 하는 패턴이다. 개별 인스턴스가 가벼워진다는 뜻에서 경량이라 부른다.

### 내부 동작
```csharp
class TreeType   // 종류당 하나: 내재 상태
{
    Mesh mesh; Texture bark; Texture leaves;
}

class Tree       // 나무마다 하나: 외재 상태 + 공유 객체 참조
{
    TreeType type;
    Vector3 position; Quaternion rotation; float scale; Color tint;
}
```

### 흔한 오해/함정
"모든 나무가 쓰니까 공유한다"는 설명은 결과를 다시 말한 것일 뿐 기준이 아니다. 종류가 여러 개가 되면 바로 성립하지 않는다. 또 메모리가 줄어드는 이유를 말할 때 "공유하니까 준다"에서 멈추면 안 되고, 원래 무엇이 몇 벌 있었는지를 따져야 한다.
