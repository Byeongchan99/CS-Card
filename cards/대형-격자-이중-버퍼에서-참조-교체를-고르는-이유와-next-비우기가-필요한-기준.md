## 질문
1000×1000 격자의 셀룰러 오토마타를 이중 버퍼로 갱신한다. 매 프레임 모든 칸의 다음 상태를 이웃의 현재 상태로 계산해 `_next`에 기록한다. Swap을 "내용 복사"로 구현하는 것과 "두 배열의 참조 맞바꾸기"로 구현하는 것 중 무엇을 골라야 하는가? 참조를 맞바꾸면 교체 직후 `_next`에 두 프레임 전 상태가 남는데, 이를 비워야 하는가? 비우기가 필요한 경우와 필요 없는 경우를 가르는 기준은 무엇인가?

```csharp
bool[,] _current = new bool[1000, 1000];
bool[,] _next    = new bool[1000, 1000];

void Step()
{
    for (int y = 0; y < 1000; y++)
        for (int x = 0; x < 1000; x++)
            _next[x, y] = Rule(_current, x, y);

    Swap();
}
```

## 핵심 답변
참조 교체를 고른다. 복사는 매 프레임 100만 칸을 읽고 쓰는 O(N)의 시간과 대역폭을 쓰지만, 참조 교체는 셀 수와 무관하게 O(1)이다. 이 예에서는 `_next`를 비울 필요가 없다. 모든 칸이 매 프레임 무조건 덮어쓰이므로, 남아 있는 옛 값은 읽히기 전에 전부 사라진다. 기준은 쓰기 단계의 성격이다. 모든 원소를 무조건 새 값으로 쓰면 비우기가 필요 없다. 이벤트가 있을 때만 일부를 쓰거나 누적해서 쓰면 비워야 한다.

## 정리
### 내부 동작
```csharp
void Swap()
{
    (_current, _next) = (_next, _current);   // 배열 참조 두 개만 맞바꾼다
}
```

### 왜 그런가
비우기가 필요한 이유는 "쓰이지 않은 원소의 잔재가 이번 세대의 결과로 오인되는 것"을 막기 위해서다. 전체 덮어쓰기에는 쓰이지 않은 원소가 없으므로 오인될 잔재도 없다. 반면 피격 플래그처럼 `Slap()`이 호출될 때만 쓰는 상태, 또는 `|=`, `+=`로 누적하는 상태는 쓰이지 않은 원소에 이전 세대 값이 그대로 남는다.

### 흔한 오해/함정
복사 방식의 비용을 "메모리 사용량"이라고 말하는 것은 틀리다. 배열 두 개는 어느 방식이든 이미 있다. 복사의 비용은 공간이 아니라 매 프레임의 시간과 메모리 대역폭이다.
