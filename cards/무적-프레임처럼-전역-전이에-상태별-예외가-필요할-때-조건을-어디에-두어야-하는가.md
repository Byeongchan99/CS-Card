## 질문
피격 전이를 상태 머신의 전역 단계로 올렸는데, 대시 중에는 무적이어야 하고 경직 중에는 재피격되면 안 된다. 이 예외를 어떻게 설계해야 하며, 그 설계는 전역 검사로 얻은 중복 제거 이득을 얼마나 반납하는가?

## 핵심 답변
검사 로직은 전역에 그대로 두고 상태별 차이는 값 하나로 표현한다. 여기서 그 값을 누가 소유하느냐가 설계를 가른다. 상태가 Enter에서 켜고 Exit에서 끄는 push 방식은 동기화 대상을 만들고, Exit가 호출되지 않는 경로가 하나라도 있으면 플래그가 켜진 채 남아 영구 무적 버그가 된다. 머신이 현재 상태에게 매 프레임 물어보는 pull 방식은 동기화할 필드가 없어 desync가 구조적으로 불가능하고, 기본값을 true로 두면 새 상태에 아무 의무도 생기지 않아 중복 제거 이득을 온전히 유지한다.

## 정리

### 왜 그런가
push 방식은 상태와 플래그라는 두 개의 진실이 생기고, 둘이 어긋날 수 있는 경로가 존재한다.

```csharp
// push — 상태가 머신의 필드를 갱신한다
public class DashState : ICharacterState
{
    public void Enter() { _machine.IsInvincible = true; }
    public void Exit()  { _machine.IsInvincible = false; }
}
```

Exit가 호출되지 않고 상태가 리셋되는 경로는 실무에 흔하다. 사망 처리, 컷신 강제 진입, 오브젝트 풀 반환 후 재사용, 씬 전환이 그렇다. 이 중 하나만 뚫려도 플래그가 켜진 채 남고 결과는 영구 무적인데, 원인은 대시 코드에 없어서 추적이 어렵다.

### 내부 동작
pull 방식은 값을 상태가 소유하고 머신이 조회만 한다.

```csharp
public abstract class CharacterStateBase
{
    public virtual bool CanBeHit => true;          // 새 상태는 신경 쓸 필요 없음
    public virtual bool CanBeInterrupted => true;
}

public class DashState : CharacterStateBase
{
    private float _elapsed;

    // 선딜 0.05초는 맞고, 이후 0.2초만 무적
    public override bool CanBeHit => _elapsed < 0.05f || _elapsed >= 0.25f;
}
```

```csharp
// 머신은 매 프레임 현재 상태에게 물어본다
if (_damageQueue.HasHit && _current.CanBeHit)
    ChangeState(_hitState);
```

pull이라야 상태 단위보다 세밀한 해상도가 표현된다. 실제 액션 게임의 무적 프레임은 대시 전체가 아니라 대시의 일부 구간이고, Enter와 Exit에서 켜고 끄는 값은 상태 단위 해상도라 이 구간을 애초에 표현할 수 없다.

### 트레이드오프
push는 검사 비용이 필드 읽기 한 번으로 가장 싸지만 동기화 위험을 진다. pull은 매 프레임 가상 프로퍼티 호출이 들어가지만 desync가 불가능하다. 캐릭터 하나 단위에서는 후자의 비용이 무시 가능하므로 pull이 기본 선택이다.

기본값 설계도 이득 유지에 중요하다. push 버전은 모든 신규 상태가 켜고 끄기를 기억해야 하므로 얇지만 중복 의무를 반납한다. pull에 기본 구현 true를 두면 그 의무조차 사라진다.

### 흔한 오해/함정
대시의 무적과 경직 중 재피격 억제는 의미가 다르다. 전자는 판정 자체가 안 맞는 것이고, 후자는 데미지는 들어가되 상태 전이만 다시 하지 않는 것이다. bool 하나에 둘을 얹으면 반드시 나중에 갈라지므로 CanBeHit과 CanBeInterrupted를 처음부터 분리하는 편이 낫다.

기본 인터페이스 멤버로 기본값을 주는 방법은 C# 8 기능으로 Unity 2021.2부터 지원되어 Unity 6에서는 사용 가능하지만, API 호환성 레벨 설정에 따라 걸리는 경우가 있어 추상 클래스의 virtual 프로퍼티가 더 무난하다.
