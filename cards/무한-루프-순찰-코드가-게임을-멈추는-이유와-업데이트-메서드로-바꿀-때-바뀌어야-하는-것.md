## 질문
해골 경비병의 왕복 순찰을 아래처럼 구현했다. 이 코드를 게임에 그대로 넣으면 무엇이 문제인가? 그리고 매 프레임 호출되는 `Update()` 형태로 바꾸려면 코드 구조에서 반드시 무엇이 바뀌어야 하는가?

```csharp
void Patrol()
{
    while (true)
    {
        for (int x = 0; x < 100; x++) skeleton.SetX(x);
        for (int x = 100; x > 0; x--) skeleton.SetX(x);
    }
}
```

## 핵심 답변
`Patrol()`은 영원히 반환하지 않는다. 그래서 같은 스레드의 게임 루프가 다음 단계인 다른 객체 갱신, 렌더링, 다음 프레임 입력으로 넘어가지 못하고 게임이 멈춘다. 해결하려면 무한 루프를 없애고, 한 번 호출될 때 한 프레임 분량만 진행한 뒤 반환하게 바꿔야 한다. 그러려면 원래 스택(지역 변수 `x`)과 실행 위치(어느 `for`문인가)에 있던 상태를 객체의 필드인 위치와 방향으로 옮겨야 한다. 이동 속도 문제는 그다음이고, `Time.deltaTime`으로 해결한다.

## 정리
### 왜 그런가
게임 루프는 모든 객체가 하나의 프레임 시간을 나눠 쓰는 구조다. 어떤 객체 하나라도 제어권을 돌려주지 않으면 그 프레임은 끝나지 않는다.

### 내부 동작
```csharp
private float _x;
private bool _movingRight = true;   // 원래는 '어느 for문인가'에 숨어 있던 상태

void Update()
{
    float step = _speed * Time.deltaTime;
    _x += _movingRight ? step : -step;
    if (_x >= _maxX) { _x = _maxX; _movingRight = false; }
    if (_x <= _minX) { _x = _minX; _movingRight = true; }
}
```

### 흔한 오해/함정
"반복문이 너무 빨리 돌아서 속도를 제어할 수 없다"는 실제 증상이 아니다. 루프가 끝나지 않으므로 렌더링 자체가 일어나지 않는다. 속도는 제어권을 돌려준 이후에 생기는 두 번째 문제다.
