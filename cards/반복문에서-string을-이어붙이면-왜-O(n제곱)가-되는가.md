## 질문
아래 루프가 성능·GC 관점에서 나쁜 이유를 설명하라. 할당이 대략 몇 개 생기고, 총 복사 비용은 어떤 복잡도인가?

```csharp
string result = "";
for (int i = 0; i < 10000; i++)
{
    result += i.ToString();
}
```

## 핵심 답변
`string`이 불변이라 `result += ...`가 매 반복 기존 문자열을 수정하지 못하고 새 객체를 만든다. 여기에 `i.ToString()`도 매 반복 임시 문자열을 만들어, 반복당 2개씩 약 20000개의 문자열 객체가 힙에 쌓인다. 더 중요한 것은 총 복사량이다. `+=`가 새 객체를 만들 때 기존 `result` 전체를 새 버퍼로 복사하는데, `result` 길이가 반복마다 자라므로 복사량이 1+2+...+n으로 누적되어 O(n²)가 된다. 객체 개수는 O(n)이지만 실제 복사 바이트는 O(n²)다.

## 정리

### 왜 그런가
불변성 때문에 이어붙이기가 "기존 객체 수정"이 아니라 "새 객체 생성 + 기존 내용 전체 복사"가 된다. 매 반복 전체 복사가 강제되고, 복사 대상인 `result`의 길이가 계속 커지기 때문에 복사 비용이 반복마다 증가한다.

### 내부 동작
```
반복 1: 길이 ~1 복사
반복 2: 길이 ~2 복사
...
반복 n: 길이 ~n 복사
복사 총합: 1 + 2 + 3 + ... + n = O(n²)
```
할당 종류는 두 가지다. `i.ToString()`의 임시 string(약 n개)과 `+=` 결과 string(약 n개), 합쳐서 약 2n개. 이 객체들은 모두 GC가 수거할 쓰레기가 된다.

### 실무(게임 개발)에서 생기는 문제와 해결
매 프레임 경로에서 로그·UI 텍스트·직렬화 문자열을 루프로 이어붙이면 이 O(n²)가 프레임 스파이크와 GC 압박으로 나타난다. 해결은 `StringBuilder`로, 최종 길이를 알면 초기 용량을 미리 잡아 확장 자체를 없앤다.

### 흔한 오해/함정
`string +=`가 언제나 나쁜 것은 아니다. 반복 횟수가 작은 상수면 무시할 만하다. 문제는 반복 횟수가 입력 크기에 비례해 커질 때 O(n²)가 드러나는 것이다. 또한 개수(O(n))만 세고 넘어가면 진짜 비용인 복사량(O(n²))을 놓친다.
