## 질문
커맨드가 실행 전 상태를 저장해 undo를 구현할 때, 그 기록은 언제 어디서 해야 하는가? 그리고 `Transform` 같은 참조 타입의 상태를 기록할 때 무엇을 주의해야 하는가?

## 핵심 답변
기록은 생성자가 아니라 `Execute()` 안에서 상태를 변경하기 직전에 해야 한다. 생성자에서 기록하면 커맨드가 큐에서 대기하는 동안 대상이 움직여 기록이 낡은 값이 된다. 기록 대상은 `Transform` 참조가 아니라 `transform.position`이라는 값이어야 한다. 참조를 담으면 그것은 상태의 복사가 아니라 살아 있는 객체로의 창구이므로 나중에 읽을 때 이미 변한 값을 읽는다.

## 정리

### 내부 동작
```csharp
public void Execute()
{
    _previousPosition = _target.position;  // 변경 직전, 값으로 복사
    _target.position += _direction * _distance;
}

public void Undo() => _target.position = _previousPosition;
```

### 왜 그런가
생성 시점과 실행 시점이 분리되는 것이 커맨드 패턴의 성질이므로, 실행 전 상태라는 개념도 실행 시점에 붙어야 의미를 가진다. 생성 시점의 상태는 실행 전 상태가 아니다.

### 흔한 오해/함정
"값 타입이면 안전하다"는 정리는 반만 맞다. `Vector3`은 struct라 대입이 곧 복사지만, 값 타입이어도 내부에 배열이나 클래스 참조를 품고 있으면 대입은 얕은 복사이고 내부 데이터는 계속 공유된다. 판단 기준은 값 타입 여부가 아니라 저장한 내용이 이후의 변경과 분리되는가다. 컬렉션이나 복합 상태를 스냅샷할 때는 명시적 깊은 복사가 필요하다.

### 트레이드오프
스냅샷을 깊게 뜰수록 안전하지만 비용이 커진다. 대상 상태가 크면 전체 스냅샷 대신 변경된 필드만 기록하는 델타 방식을 쓰고, 대신 어떤 필드를 건드렸는지 커맨드가 정확히 알아야 한다는 제약을 진다.
