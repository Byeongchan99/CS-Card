## 질문
유니티에서 싱글턴 GameManager가 MonoBehaviour를 상속하면 static 클래스 버전에서는 쓸 수 없던 어떤 기능들을 구체적으로 쓸 수 있는가? static 클래스가 그 기능들을 쓸 수 없는 이유를 언어(C#) 쪽과 엔진 쪽으로 나눠 설명하라.

## 핵심 답변
Inspector 직렬화(`[SerializeField]`로 튜닝 값과 프리팹·에셋 참조를 에디터에서 연결), `Awake`/`Start`/`Update`/`OnDestroy` 같은 생명주기 메시지, 코루틴(`StartCoroutine`), 그리고 GameObject·씬 소속에 따른 수명 관리(`DontDestroyOnLoad`)를 쓸 수 있다. 언어 쪽에서는 static 클래스가 `object` 외의 클래스를 상속할 수 없으므로 MonoBehaviour 상속 자체가 컴파일 단계에서 막힌다. 엔진 쪽에서는 유니티가 GameObject에 붙은 컴포넌트 인스턴스를 들고 그 인스턴스에 메시지를 호출하고 필드에 직렬화 데이터를 써 넣으므로, 인스턴스가 없으면 끼어들 방법이 없다.

## 정리
### 내부 동작
씬에 배치된 컴포넌트는 네이티브 객체와 C# 래퍼 객체의 쌍으로 존재한다. 엔진은 네이티브 쪽에서 컴포넌트 목록을 관리하고, 해당 래퍼 인스턴스의 메서드를 메시지로 호출한다. 직렬화 역시 특정 인스턴스의 필드를 대상으로 한다. `StartCoroutine`은 MonoBehaviour의 인스턴스 메서드라서, 코루틴은 그것을 시작한 컴포넌트에 소속되어 돈다.

### 실무(게임 개발)에서 생기는 문제와 해결
매니저를 MonoBehaviour로 만드는 가장 흔한 이유는 Inspector 연결과 코루틴이다. 디버깅용 튜닝 값을 코드 수정 없이 바꾸고, 오디오 클립이나 프리팹 같은 에셋 참조를 에디터에서 꽂을 수 있다. 대신 씬과 함께 생기고 사라지는 수명을 떠안게 되므로 중복 제거와 파괴 순서를 직접 다뤄야 한다.

### 흔한 오해/함정
"컴포넌트 시스템을 쓸 수 있다"처럼 범주로만 답하면 구체성이 없다. Inspector 직렬화, 생명주기 메시지, 코루틴처럼 기능 이름으로 말해야 한다.
