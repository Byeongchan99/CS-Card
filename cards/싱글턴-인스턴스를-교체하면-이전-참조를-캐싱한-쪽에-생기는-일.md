## 질문
순수 C# 싱글턴 GameState에 `StartNewGame() => Instance = new GameState();`가 있다. GoldHUD는 `Awake`에서 `_state = GameState.Instance;`로 참조를 받아 두고 매 프레임 `_state.Gold`를 표시하고, Shop은 매번 `GameState.Instance.Gold -= 50`을 한다. Gold가 340일 때 새 게임을 시작하고 한 번 구매하면 HUD와 실제 값은 각각 얼마인가? 왜 예외가 나지 않는가? 이전 GameState는 GC가 회수하는가?

## 핵심 답변
HUD는 340, 실제 `Instance.Gold`는 50이다. HUD는 교체 전 객체를 계속 읽고 Shop은 새 객체를 바꾼다. 예외가 나지 않는 이유는 순수 C# 객체에는 "파괴됨"이라는 상태가 없기 때문이다. 유니티 오브젝트는 엔진이 파괴 사실을 네이티브 쪽에 기록하고 오버로딩된 `==`가 확인해 주지만, 순수 C# 객체는 GC가 아는 생사가 도달 가능성 하나뿐이다. HUD가 참조를 붙잡고 있으므로 이전 객체는 도달 가능하고 회수되지 않는다.

## 정리
### 내부 동작
```
StartNewGame 이전:  Instance ──▶ [GameState#1 Gold=340] ◀── GoldHUD._state
StartNewGame 이후:  Instance ──▶ [GameState#2 Gold=100→50]
                                 [GameState#1 Gold=340] ◀── GoldHUD._state (계속 생존)
```

### 실무(게임 개발)에서 생기는 문제와 해결
결과는 메모리 누수보다 조용한 상태 분열이다. 화면과 로직이 다른 값을 보면서 아무 경고 없이 게임이 진행된다. 해결은 세 방향이다. 참조를 캐싱하지 않고 매번 `Instance`로 접근하거나, 교체 시 이벤트를 발행해 구독자가 새 인스턴스를 다시 받게 하거나, 인스턴스를 고정하고 내부 상태만 리셋한다. 마지막 방식은 리셋 누락 위험이 돌아오므로, 상태를 내부 데이터 객체 하나로 묶어 그것만 교체하는 절충도 쓴다.

### 흔한 오해/함정
"교체된 객체는 죽은 객체"라는 것은 프로그래머의 의도일 뿐이다. 런타임은 그 의도를 알 방법이 없어서 신호를 줄 수 없다.
