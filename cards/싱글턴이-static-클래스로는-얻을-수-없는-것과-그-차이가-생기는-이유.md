## 질문
유니티의 GameManager처럼 "전역에서 하나만 존재하고 어디서든 접근한다"는 목적이 같을 때, 인스턴스 하나를 `Instance`로 노출하는 싱글턴은 모든 멤버를 static으로 둔 static 클래스로는 얻을 수 없는 무엇을 얻는가? 그 차이는 왜 생기는가?

## 핵심 답변
static 클래스는 타입에 묶인 멤버 모음이고, 싱글턴은 실제 객체 하나다. 객체이기 때문에 인터페이스 구현과 다형성, 참조로 넘기기(주입), 다른 클래스 상속이 가능하고, 유니티에서는 MonoBehaviour를 상속해 Inspector 직렬화, 생명주기 메시지, 코루틴을 쓸 수 있다. 또 객체이므로 생성·교체·파괴 시점을 코드가 정할 수 있는 반면, static 클래스의 초기화는 CLR이 정한 시점에 한 번만 일어난다.

## 정리
### 왜 그런가
C#의 static 클래스는 abstract sealed로 컴파일되어 인스턴스를 만들 수 없고, `object` 외의 클래스를 상속할 수 없으며, 인터페이스도 구현할 수 없다. 인스턴스가 없으니 값으로 넘길 대상도 없다. 싱글턴의 능력은 전부 "객체가 하나 존재한다"는 사실에서 나온다.

### 트레이드오프
static 클래스는 단순하고 접근 비용이 가장 싸다. 상태가 없는 유틸리티(수학 함수, 확장 메서드)에는 static 클래스가 맞다. 상태를 들고 생명주기·교체·주입이 필요할 때 싱글턴이 의미가 있다.

### 흔한 오해/함정
싱글턴이 객체라고 해서 static의 문제에서 자유로운 것은 아니다. 인스턴스를 붙잡는 `Instance` 자체가 static 필드이므로, 상태의 수명은 결국 static 필드의 수명을 따른다. [[도메인 리로드를 끄면 static 클래스와 싱글턴의 상태가 플레이 사이에 남는 이유]]
