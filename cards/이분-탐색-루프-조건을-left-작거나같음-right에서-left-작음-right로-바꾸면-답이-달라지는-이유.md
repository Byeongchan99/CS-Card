## 질문
"조건 만족 시 후보를 기록하고 `left = mid + 1` / `right = mid - 1`로 좁히는" 이분 탐색에서, 루프 조건만 `while (left <= right)`에서 `while (left < right)`로 바꾸면 답이 달라지는 입력이 생긴다. 왜 그런가?

## 핵심 답변
탐색 구간을 닫힌 구간 `[left, right]`로 보고 전부 소진하는 스타일에서, `left == right`인 순간은 "아직 검사하지 않은 원소가 정확히 하나 남은 상태"다. `<=`는 이 마지막 한 칸을 mid로 잡아 검사한 뒤 종료하지만, `<`는 `left == right`가 되는 순간 그 칸을 건드리지 않고 루프를 끊는다. 그래서 마지막 한 칸이 정답 후보일 때 그것을 놓친다.

## 정리

### 내부 동작
`a = [1,3,5,7]`, `x = 7`:
```
초기:  left=0, right=3, answer=-1
[1회]  mid=1, a[1]=3 ≤ 7 → answer=1, left=2
[2회]  mid=2, a[2]=5 ≤ 7 → answer=2, left=3
[3회]  left==right==3
       <= 버전: 조건 참 → mid=3, a[3]=7 ≤ 7 → answer=3 (정답)
       <  버전: 조건 거짓 → 즉시 종료 → answer=2 (오답)
```

### 흔한 오해/함정
조건 하나만 `<`로 바꾸면 항상 이 실패로 이어지는 건 아니다. 예컨대 `x = 1`도 두 버전의 답이 갈리지만, 그건 `left == right`까지 좁혀지기 전에 다른 경로로 끝나서다. "마지막 한 칸 누락"이라는 결함을 실제로 밟는 입력은 `x = 7`처럼 `left == right`에 정답 후보가 남는 경우다. 진단(마지막 칸 누락)과 그 진단이 발동하는 입력을 혼동하지 않아야 한다.

### 트레이드오프
경계 조건(`<=`/`<`), 갱신식(`mid+1`/`mid-1`/`mid`), 답을 읽는 시점 이 세 가지는 한 몸이다. `<` 스타일을 쓰려면 갱신 규칙과 답 확정 시점을 세트로 다시 설계해야 한다. 아무 스타일에나 `<`만 끼워 넣으면 마지막 한 칸이 항상 사각지대가 된다.
