## 질문
폭탄 100개가 일렬로 놓여 있고, 하나가 터지면 옆 폭탄을 터뜨린다. 폭발 상태를 이중 버퍼로 관리하므로 연쇄가 한 프레임에 한 칸씩만 전파되어, 60fps에서 끝까지 약 1.7초가 걸린다. "연쇄 전체가 같은 프레임 안에 터지되, 결과가 갱신 순서에 따라 달라지면 안 된다"는 요구를 만족시키려면 갱신 루프를 어떻게 바꿔야 하는가? 그 방식의 비용은 무엇이고 최악의 경우 어떻게 커지는가?

## 핵심 답변
"갱신 → 교체"를 프레임당 한 번이 아니라, 한 프레임 안에서 새 변화가 없을 때까지 반복한다. 반복 한 번이 연쇄 한 단계이므로 순서 독립성은 유지된다. 매 반복마다 N개를 전부 검사하면 비용은 N × 연쇄 길이가 되어, 일렬 연쇄 같은 최악의 경우 O(N²)이 된다. 이번 단계에 새로 터진 폭탄만 다음 단계에서 검사하면 레벨 단위 BFS와 같은 구조가 되어 O(N + 간선)으로 줄어든다.

## 정리
### 내부 동작
```
고정점 반복
  do {
      changed = 모든 폭탄 Update (current 읽기, next 쓰기)
      Swap
  } while (changed && 반복 횟수 < 상한)

레벨 단위 BFS
  frontier = 이번 프레임에 처음 터진 폭탄들
  while (frontier 비어있지 않음) {
      nextFrontier = frontier의 이웃 중 아직 안 터진 것 (방문 표시)
      frontier = nextFrontier      ← 한 레벨 = 이중 버퍼의 한 세대
  }
```

### 왜 그런가
이중 버퍼의 순서 독립성은 "한 세대 안에서는 이전 세대 값만 읽는다"에서 나온다. 세대를 프레임과 분리해서 한 프레임 안에 여러 세대를 돌려도 이 성질은 유지된다. BFS의 레벨 구분도 정확히 같은 역할을 한다. 같은 레벨의 노드는 서로의 처리 결과를 보지 않고, 이전 레벨의 결과만 본다.

### 실무(게임 개발)에서 생기는 문제와 해결
반복 비용이 한 프레임에 몰려 스파이크가 생길 수 있다. 그래서 반복 횟수에 상한을 두고 남은 전파는 다음 프레임으로 넘기는 안전장치를 함께 둔다. BFS 방식에서는 같은 폭탄이 두 번 터지지 않도록 방문 표시가 필요하다.

### 흔한 오해/함정
최종적으로 터지는 폭탄의 집합은 도달 가능성으로 정해지므로 처리 순서와 무관하다. 그러나 피해 누적이나 효과음 재생 순서처럼 폭발마다의 부수 효과가 처리 순서에 민감하다면, 큐에 넣은 순서가 결과를 바꿀 수 있다. 이런 경우에는 레벨 단위로 끊어 처리해서 결정성을 지켜야 한다.
