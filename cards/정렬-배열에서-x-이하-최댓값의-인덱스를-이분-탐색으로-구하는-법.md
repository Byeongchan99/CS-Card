## 질문
오름차순·중복 없는 정수 배열에서 "x 이하인 원소 중 가장 큰 값의 인덱스"(없으면 -1)를 구하려 한다. "값이 정확히 x인 원소의 인덱스를 찾고 없으면 -1"을 하는 표준 이분 탐색으로는 그대로 풀리지 않는 이유는 무엇이고, 루프는 구조적으로 무엇을 다르게 해야 하는가?

## 핵심 답변
표준 이분 탐색은 `a[mid] == x`를 만나면 즉시 종료하지만, 이 문제는 등호가 아니라 부등호(`<= x`) 질의라 배열에 x가 없어도 답이 나와야 한다. 그래서 "찾으면 종료"가 아니라 "조건을 만족하면 그 인덱스를 답 후보로 기록하고 계속 좁힌다"는 골격을 쓴다. `a[mid] <= x`이면 `answer = mid`로 기록하고 `left = mid + 1`로 더 큰 인덱스를 계속 찾고, `a[mid] > x`이면 `right = mid - 1`로 왼쪽을 본다. `answer` 초기값 -1이 "조건을 만족하는 원소가 없음"을 자연히 처리한다.

## 정리

### 왜 그런가
predecessor(floor) 질의는 배열에 x가 존재하지 않아도 답이 존재한다. "정확히 일치하면 종료"라는 표준형은 이 경우를 다루지 못한다. 그래서 일치 여부가 아니라 부등식 조건을 만족하는 마지막 위치, 즉 경계를 찾는 문제로 바꾼다.

### 내부 동작
```csharp
int left = 0, right = a.Length - 1, answer = -1;
while (left <= right)
{
    int mid = left + (right - left) / 2;
    if (a[mid] <= x) { answer = mid; left = mid + 1; }  // 후보 기록, 더 큰 인덱스로
    else             { right = mid - 1; }
}
return answer;
```
`a = [1,3,5,7]`, `x = 4`: mid=1(a=3)에서 answer=1, left=2 → mid=2(a=5>4)에서 right=1 → 종료. answer=1(값 3).

### 흔한 오해/함정
이 문제를 "중복된 목표 값의 최오른쪽 위치 찾기"로 착각하기 쉽다. 손동작(후보 기록 후 `left=mid+1`)은 우연히 같지만, 이 문제엔 정확히 일치하는 목표 값이 없고 조건이 부등호라는 점이 다르다. 그래서 x가 배열에 아예 없어도 답이 나온다.
