## 질문
게임 상태(Score, Stage, Gold)를 static 클래스(정적 생성자에서 초기값 설정)와 순수 C# 싱글턴(필드 초기화 식으로 초기값 설정) 두 방식으로 만들었다. static 클래스의 정적 생성자는 언제, 누구에 의해, 몇 번 실행되는가? "새 게임"으로 모든 상태를 초기값으로 되돌릴 때 각각 어떻게 하며, 필드가 30개로 늘고 계속 추가된다면 어느 쪽이 왜 버그가 덜 생기는가?

## 핵심 답변
정적 생성자는 CLR이 그 타입의 정적 멤버에 처음 접근하기 직전에 자동으로 실행하며, 한 AppDomain 안에서는 다시 실행되지 않는다. 그래서 static 클래스는 별도의 `Reset()`을 만들어 초기값을 정적 생성자와 Reset 양쪽에 중복해 적어야 하고, 필드를 추가할 때 Reset에 빠뜨리기 쉽다. 싱글턴은 `Instance = new GameState()`로 새 객체를 만들면 필드 초기화 식 전체가 자동으로 다시 적용되므로 누락이 구조적으로 사라진다. 단 기존 인스턴스를 캐싱한 쪽이 있으면 교체 방식이 새 문제를 만든다.

## 정리
### 왜 그런가
초기값을 설정하는 코드가 정적 생성자인지, 인스턴스 생성 과정인지의 차이다. 정적 생성자는 개발자가 다시 호출할 방법이 없지만, 인스턴스 생성은 `new`로 몇 번이든 반복할 수 있다.

### 트레이드오프
교체 방식은 리셋 누락을 없애는 대신 "이전 객체를 들고 있는 쪽"이라는 새 위험을 만든다. 인스턴스를 고정하고 Reset 메서드로 필드를 되돌리는 방식은 참조 안정성은 지키지만 누락 위험이 돌아온다.

### 흔한 오해/함정
정적 생성자의 "한 번"은 프로그램 실행당이 아니라 AppDomain당이다. 유니티 에디터에서 도메인 리로드를 끄면 플레이를 다시 시작해도 정적 생성자가 다시 돌지 않는다.
