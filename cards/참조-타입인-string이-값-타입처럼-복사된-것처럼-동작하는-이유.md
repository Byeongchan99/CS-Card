## 질문
`string`은 C#에서 참조 타입(class)이다. 그런데 `string b = a;` 후 `b`를 수정해도 `a`는 그대로다. 참조 타입인데 왜 값 타입처럼 "복사된 것처럼" 동작하는가? 내부에서 무슨 일이 일어나는지 설명하라.

```csharp
string a = "hello";
string b = a;
b += " world";
Console.WriteLine(a);  // "hello"
```

## 핵심 답변
`string`은 참조 타입이지만 불변(immutable)이다. `string b = a`는 문자열 내용이 아니라 참조만 복사하므로, 이 시점에는 `a`와 `b`가 힙의 같은 객체를 가리킨다. `b += " world"`는 불변이라 기존 객체를 수정하지 못하고 새 문자열 객체를 만들어 `b`의 참조만 거기로 갈아끼운다. `a`는 여전히 원래 객체를 가리키므로 값이 유지된다. 값 의미론처럼 보이는 것은 복사가 아니라 불변성에서 나온다.

## 정리

### 왜 그런가
겉보기의 값 동작을 만드는 것은 두 가지의 조합이다. 첫째, 대입은 참조만 복사한다(내용 복사 아님). 둘째, string은 불변이라 어떤 연산도 기존 객체를 수정할 수 없고 항상 새 객체를 만든다. 그래서 한쪽의 재할당이 다른 쪽이 가리키는 객체에 영향을 주지 못한다.

### 내부 동작
```
string a = "hello";   a ──→ ["hello"]
string b = a;         b ──→ ["hello"]        (같은 객체를 가리킴)
b += " world";        b ──→ ["hello world"]  (새 객체 생성 후 b의 참조 교체)
                      a ──→ ["hello"]        (변화 없음)
```

### 흔한 오해/함정
`string b = a`에서 문자열이 복사된다고 생각하기 쉬우나, 복사되는 것은 참조뿐이다. 이 순간 두 변수는 같은 객체를 공유한다. 복사처럼 보이는 결과는 이후 `+=`가 새 객체를 만들기 때문에 사후적으로 나타나는 것이다.
