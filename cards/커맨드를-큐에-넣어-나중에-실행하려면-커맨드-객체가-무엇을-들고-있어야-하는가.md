## 질문
요청을 객체로 만들어 큐에 넣어두고 나중에 실행하려면, 실행 시점에 필요한 모든 것이 커맨드 객체 안에 이미 있어야 한다. 그 "모든 것"은 구체적으로 무엇인가? `MoveCommand`를 예로 필드 단위로 답해라.

## 핵심 답변
누구에게 보내는 요청인지를 가리키는 Receiver 참조와, 무엇을 얼마나 하는지를 담은 실행 인자다. `MoveCommand`라면 대상 `Transform`, 이동 방향, 이동 거리다. 생성 시점에 이 값들을 고정하면 요청이 발생한 순간의 의도가 동결되어 실행 시점이 언제든 같은 결과가 재현된다. undo까지 지원하려면 실행 전 상태를 담을 필드가 하나 더 필요하다.

## 정리

### 내부 동작
```csharp
public class MoveCommand : ICommand
{
    private readonly Transform _target;   // Receiver
    private readonly Vector3 _direction;  // 인자
    private readonly float _distance;     // 인자

    public MoveCommand(Transform target, Vector3 direction, float distance)
    {
        _target = target;
        _direction = direction;
        _distance = distance;
    }

    public void Execute() => _target.position += _direction * _distance;
}
```

### 왜 그런가
커맨드가 만들어지는 시점과 실행되는 시점이 분리되는 것이 이 패턴의 핵심 이점이다. 그 분리가 성립하려면 커맨드가 실행에 대해 자기 완결적이어야 한다. 인자를 필드로 갖지 않고 실행 시점에 전역 상태나 현재 입력에서 읽어오면, 대기하는 동안 그 값이 바뀌어 원래 의도와 다른 일이 벌어진다.

### 실무(게임 개발)에서 생기는 문제와 해결
턴제 게임이나 입력 버퍼링에서 커맨드는 생성 후 몇 프레임 뒤에 실행된다. 리플레이에서는 며칠 뒤에 실행될 수도 있다. 자기 완결적이지 않은 커맨드는 큐잉과 리플레이가 동시에 깨진다.

### 트레이드오프
인자를 동결하면 재현성은 얻지만, 실행 시점의 최신 상황을 반영하지 못한다. 실행 시점의 상황을 봐야 하는 로직은 커맨드 안이 아니라 Receiver 쪽에 두어야 한다.
