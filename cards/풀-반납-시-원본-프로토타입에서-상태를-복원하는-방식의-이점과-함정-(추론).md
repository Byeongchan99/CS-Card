## 질문
프로토타입 레지스트리에서 `Clone()`으로 몬스터를 찍어내다가 할당을 줄이려고 오브젝트 풀을 붙였다. 반납된 몬스터의 상태를 레지스트리의 원본 프로토타입에서 다시 복사해 오는 `ResetFrom(Monster prototype)`으로 리셋하자는 제안이 있다. (`Monster`는 Hp, Weapon, Buffs, StatTable, Name을 가진다.) 이 방식이 얻는 것은 무엇이고, 원본 필드를 그대로 대입하면 어떤 문제가 생기며, 그 문제를 깊은 복사로 피하면 풀링의 목적과 어떤 긴장이 생기는가?

## 핵심 답변
초기값의 원천이 원본 하나로 유지되어 원본을 고치면 리셋 결과도 따라간다. 하지만 참조형 필드를 그대로 대입하면 모든 풀 인스턴스가 원본의 Weapon과 Buffs를 공유하고, 한 마리가 무기를 쓰는 순간 원본이 닳아 이후 모든 리셋이 오염된 값으로 복원된다. 리셋마다 `new`로 깊은 복사하면 공유는 끊기지만 반납마다 할당이 생겨 풀링의 목적과 부딪힌다. 해법은 인스턴스가 이미 가진 객체에 원본의 값만 부어 넣는 것이다.

## 정리
### 내부 동작
```csharp
// 원본의 초기 상태를 이 인스턴스가 이미 가진 객체들에 덮어써서 할당 없이 복원한다
public void ResetFrom(Monster prototype)
{
    Hp = prototype.Hp;
    Weapon.Durability = prototype.Weapon.Durability;   // 새 Weapon을 만들지 않는다
    Buffs.Clear();                                      // 내부 배열 용량은 유지된다
    Buffs.AddRange(prototype.Buffs);
    StatTable = prototype.StatTable;                    // 공유 대상은 참조 대입
    Name = prototype.Name;                              // 불변이라 공유해도 안전
}
```

### 트레이드오프
생성 시점 `Clone()`은 새 객체를 만드는 깊은 복사, 반납 시점 `ResetFrom()`은 기존 객체에 값을 붓는 복사로 역할이 나뉜다. 대신 필드가 추가될 때마다 두 메서드를 함께 고쳐야 하고, 하나를 빠뜨리면 그 필드는 리셋되지 않거나 원본과 공유된 채 남는다.

### 흔한 오해/함정
단순 대입의 피해는 "원본과 인스턴스가 공유한다"에서 끝나지 않는다. 원본은 리셋의 기준점이므로, 원본이 오염되면 이후 리셋되는 모든 인스턴스가 오염된 상태로 복원된다.
