## 질문
몬스터 스포너가 고블린, 오크, 슬라임 등 여러 종류를 생성한다. 스포너가 `new Goblin(...)`처럼 구체 클래스 생성자를 직접 호출하는 방식 대신, `Monster` 타입의 원본 인스턴스를 들고 `prototype.Clone()`으로 복제하는 프로토타입 패턴을 쓰면 스포너는 무엇에 대한 의존을 끊게 되는가? 새 몬스터 종류나 "체력만 두 배인 엘리트 고블린" 같은 변형을 추가할 때 두 방식은 어떻게 달라지는가?

## 핵심 답변
스포너는 구체 클래스의 이름과 생성자 시그니처에 대한 의존을 끊고, `Monster` 추상 타입과 `Clone()` 계약만 알게 된다. 생성자 방식은 종류가 늘 때마다 스포너에 생성 분기를 추가해야 하지만, 프로토타입 방식은 원본을 레지스트리에 등록하기만 하면 된다. 엘리트 고블린 같은 변형은 새 클래스 없이 고블린을 복제한 사본의 상태를 바꿔 별도로 등록하면 된다. 변형이 타입이 아니라 데이터로 표현되는 것이 이 패턴의 핵심 이점이다.

## 정리
### 개념
생성을 "클래스로부터 만들기"에서 "이미 초기화된 원본을 복사하기"로 바꾸는 생성 패턴이다. 원본이 자신을 복제하는 방법을 알고 있으므로 생성하는 쪽은 원본의 구체 타입을 몰라도 된다.

```csharp
public class Spawner
{
    private readonly Dictionary<string, Monster> _prototypes = new Dictionary<string, Monster>();

    // 키에 해당하는 원본을 등록한다
    public void Register(string key, Monster prototype) => _prototypes[key] = prototype;

    // 등록된 원본을 복제해 새 몬스터를 만든다
    public Monster Spawn(string key) => _prototypes[key].Clone();
}
```

### 왜 그런가
의존이 없어지는 것이 아니라 이동한다. 누군가는 원본을 만들 때 한 번 `new Goblin()`을 호출해야 한다. 생성은 게임 곳곳에서 반복되지만 등록은 초기화 시점 한 곳이므로, 구체 타입 지식이 한 지점으로 모인다. 스포너 입장에서는 새 종류가 추가돼도 코드가 바뀌지 않으므로 OCP가 지켜진다.

### 흔한 오해/함정
엘리트를 만들겠다고 등록된 고블린 원본의 체력을 직접 두 배로 바꾸면, 이후 스폰되는 일반 고블린도 전부 엘리트가 된다. 원본은 모든 사본의 기준점이므로 반드시 복제한 사본을 가공해 새 키로 등록해야 한다.
