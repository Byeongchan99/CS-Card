# CS 퀴즈 세션 지침 (광범위 복습형)

게임 개발자 면접/테스트 대비 공부. 이 세션은 요약 노트(`summary-notes/`)의 원천이 되는
**복습 노트**를 만든다.

## 다른 트랙과의 관계
- **면접관 모드**(`docs/공부세션-지침.md`)는 한 갈래를 끝까지 파고들어 **카드 + 심화 노트**를
  만든다. 깊고 좁다.
- **이 퀴즈 세션**은 대분류를 넓게 돌며 짧은 문제를 많이 낸다. **카드가 없는 주제**(트라이,
  LRU, SOLID, 노멀맵 등)까지 얕고 넓게 훑는 것이 목적이다. 산출물은 요약 노트에 병합된다.
- 두 트랙은 독립이다. 이 세션은 카드나 index.md를 건드리지 않는다.

## 진행 방식
- 대분류(알고리즘, 자료구조, 운영체제, 유니티, C#, 디자인 패턴, 게임 수학·물리, 그래픽스)를
  돌며 한 번에 문제 하나씩 낸다.
- 답의 범위가 명확한 문제만 낸다(개념 정의, A vs B 비교, 코드 결과 예측, 짧은 원리 설명).
- 답하면 맞은 부분 / 틀린 부분 / 애매한 부분을 구분해 지적한다.
- 깊게 파고들지 않는다 — 한 주제에서 한두 번 되물어 확인하고 다음 주제로 넘어간다.
  깊게 갈 주제가 나오면 면접관 모드 세션감으로 따로 메모만 남긴다.
- 한 세션에서 한 대분류를 몰아서 돌거나 여러 대분류를 섞어도 된다.

## 세션 종료 산출물 — 복습 노트
세션이 끝나면 **대분류별로 묶은 복습 노트**를 낸다. 그대로 `/노트병합`에 넣을 수 있게
요약 노트 형식(`CLAUDE.md`의 "요약 노트" 절)에 맞춘다.

- 항목마다 `## 항목명` + 2~4문장 요약
- 헷갈렸거나 틀린 지점은 `> [!tip] 복습 포인트` 콜아웃으로 분리
- A vs B 형태의 비교는 표로
- 종결어미를 생략한 간결체 (심화 노트의 `~다`와 다르다)
- 세션 부기는 넣지 않는다 — `====` 구분선, 번호 매김, "N일차", "퀴즈 N~N번",
  "새 개념 —" 같은 접두사. 이건 사이트에서 맥락이 없다.

형식 예:

```markdown
## 트라이(Trie)
루트에서 문자를 하나씩 자식으로 내려가는 트리. 검색이 단어 수와 무관하게 길이 L에
비례(O(L)). 게임에서는 채팅 자동완성·욕설 필터.

## 퀵 vs 병합 정렬
| | 장점 | 대가 |
| --- | --- | --- |
| 퀵 | 제자리, 캐시 지역성 | 최악 O(n²) |
| 병합 | 안정 정렬, 최악 O(n log n) 보장 | 보조 배열 O(n) |

> [!tip] 복습 포인트
> 둘 다 평균 O(n log n). 배열은 퀵 계열이 선호.
```

## 사이트 반영
복습 노트를 저장소에 붙여넣고 `/노트병합`을 실행하면, 8개 분야 페이지에 항목 단위로
병합된다(같은 주제는 통합, 새 주제는 관련 항목 옆에 배치). 요약 노트 파일과 title은
대분류 이름을 그대로 쓴다(`자료구조`, `디자인 패턴` 등). 파일명만 규칙을 따른다(`C#` → `C샵`).
