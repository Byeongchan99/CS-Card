분야 핵심 개념을 얕고 넓게 정리한 노트. 쓱 훑어보며 복습한다.

항목 제목의 ★는 면접에서 개념·원리를 깊게 파고드는 축이라는 표시. 나머지도 ★ 항목의 꼬리질문에서 나오므로 건너뛰지 않는다.

## 벡터 연산

방향과 성분을 다루는 기본 도구. 투영·반사·각도는 모두 내적과 외적에서 갈라져 나온다.

### 벡터 정규화 ★

벡터에는 방향과 크기(길이) 두 정보가 담김. 정규화는 벡터를 자기 길이로 나눠 방향은 그대로 두고 길이만 1로 만드는 것이고, 결과를 단위 벡터라 부름. "방향만 쓰겠다"는 선언이다.

이동은 `방향 × 속력 × 시간`으로 계산하는데, 이 식은 방향의 길이가 1이라고 가정함. 방향에 길이가 섞여 있으면 그만큼 속력이 몰래 곱해짐. 키보드 대각선 입력 (1, 1)은 길이 √2 ≈ 1.41이라 상하좌우보다 1.41배 빠르고, 정규화하면 (0.707, 0.707)이 되어 모든 방향이 같은 속력.

```csharp
Vector2 input = new Vector2(1, 1);   // 키보드 대각선
input.magnitude;                     // ≈ 1.414
input.normalized;                    // ≈ (0.707, 0.707), 길이 1

pos += (Vector3)input * speed * dt;             // 대각선이 1.41배 빠름
pos += (Vector3)input.normalized * speed * dt;  // 모든 방향 같은 속력
```

이동 말고도 단위 벡터를 넣어야만 성립하는 공식이 많음.

- 내적 — `a·b = |a||b|cosθ`라 둘 다 길이 1일 때만 내적이 곧 cosθ. 적 방향을 정규화하지 않으면 멀리 있는 적일수록 값이 커져 시야 판정이 거리에 흔들림
- 투영·반사 — `v − (v·n)n`, `d − 2(d·n)n`은 법선 n이 길이 1이어야 함. n의 길이가 2면 빼는 양이 4배(내적에서 한 번, 다시 곱할 때 한 번)

```csharp
Vector3 toEnemy = enemy.position - transform.position;   // 길이 = 거리
Vector3.Dot(transform.forward, toEnemy);              // 거리 × cosθ, 거리에 따라 커짐
Vector3.Dot(transform.forward, toEnemy.normalized);   // cosθ, -1에서 1 사이
```

주의할 점.

- 비용 — 제곱근 한 번과 나눗셈. 크기 비교만 필요하면 정규화·길이 대신 제곱 길이(`sqrMagnitude`)로 비교해 제곱근을 피함
- 길이 0 — 0으로 나누는 셈이라 정의되지 않음. 유니티 `normalized`는 길이가 아주 작으면(약 1e-5 미만) `zero`를 돌려줘 NaN이 안 생기지만, 직접 구현하면 이 검사를 넣어야 함
- 아날로그 스틱 — 기울인 정도가 길이에 담김. 무조건 정규화하면 살짝만 기울여도 최고 속력이라 걷기·뛰기 구분이 사라짐. 길이에 상한만 거는 `ClampMagnitude`를 씀

```csharp
Vector2 stick = new Vector2(0.3f, 0f);   // 스틱을 살짝
stick.normalized;                        // (1, 0)   — 기울기 정보가 지워짐
Vector2.ClampMagnitude(stick, 1f);       // (0.3, 0) — 그대로
Vector2.ClampMagnitude(input, 1f);       // ≈ (0.707, 0.707) — 대각선만 1로 잘림
```

### 내적(dot product) ★

두 벡터를 받아 숫자 하나를 돌려주는 연산. 계산은 성분끼리 곱해 더하는 것뿐(곱셈 3번, 덧셈 2번)인데, 이 값이 항상 `|a||b|cosθ`와 같다는 게 핵심. 그래서 각도를 직접 구하지 않고도 두 방향의 관계를 싸게 알아냄.

의미는 그림자. b가 단위 벡터면 `a·b̂ = |a|cosθ`는 a를 b̂ 방향에 비춘 그림자의 부호 있는 길이. 같은 쪽에 생기면 양수, 반대쪽이면 음수, 수직이면 0. 둘 다 단위 벡터면 그림자가 곧 cosθ라 범위가 −1에서 1로 고정됨.

```csharp
Vector3 a = Vector3.right;
Vector3.Dot(a, new Vector3(1, 1, 0).normalized);  // ≈ 0.707 (45도)
Vector3.Dot(a, Vector3.up);                       // 0 (수직)
Vector3.Dot(a, -a);                               // -1 (정반대)

Vector3 v = new Vector3(3, 4, 0);
Vector3.Dot(v, Vector3.right);                    // 3, x 방향으로 3만큼 감
Vector3.Dot(v, v);                                // 25, 길이의 제곱 = sqrMagnitude
```

쓰임은 셋.

- 앞뒤 판정 — 부호는 길이와 무관하게 각도로만 정해져서 정규화도 필요 없음. `Dot(forward, toEnemy) > 0`이면 90도 안쪽
- 시야각 판정 — 범위를 볼 때는 값의 크기가 의미를 가지므로 정규화 필요. 각도 대신 코사인끼리 비교해 역코사인을 피함. 0도에서 180도 사이 코사인은 각이 커질수록 작아지므로 "각도 ≤ 반각"은 "dot ≥ cos(반각)"과 같음
- 성분 뽑기 — `v·n̂`은 v가 n̂ 방향으로 얼마나 가는가. 이 성분을 빼면 벽 슬라이딩, 두 배로 빼면 반사(아래 항목들)

```csharp
float cosHalf = Mathf.Cos(fov * 0.5f * Mathf.Deg2Rad);   // 시야각은 안 바뀌니 한 번만
Vector3 dir = (enemy.position - transform.position).normalized;
bool inView = Vector3.Dot(transform.forward, dir) >= cosHalf;
// fov 90 → cosHalf ≈ 0.707. 정면 30도 적은 0.866이라 true, 60도 적은 0.5라 false
```

함정.

- 역코사인 NaN — 오차로 내적이 1.0000001처럼 나오면 `Mathf.Acos`가 NaN. 각도가 필요하면 `Mathf.Clamp(dot, -1f, 1f)`로 자르거나 내부에서 클램프하는 `Vector3.Angle`을 씀
- 3D 시야는 원뿔 — 수평 시야만 보려면 방향의 y를 먼저 0으로 만든 뒤 정규화. 순서가 바뀌면 길이가 1보다 작아져 판정이 틀어짐

### 외적(cross product) ★

3D 벡터 두 개를 받아 벡터 하나를 돌려주는 연산(내적은 숫자를 돌려줌). 식은 `a×b = (ay·bz − az·by, az·bx − ax·bz, ax·by − ay·bx)`.

- 방향 — a와 b 둘 다에 수직. 두 벡터가 놓인 평면의 법선
- 크기 — `|a||b|sinθ`, a와 b로 만든 평행사변형의 넓이. 평행하면 0
- 순서 — `a×b = −(b×a)`, 순서를 바꾸면 정반대

```csharp
Vector3 a = new Vector3(1, 0, 0), b = new Vector3(0, 1, 0);
Vector3.Cross(a, b);       // (0, 0, 1)   둘 다에 수직
Vector3.Cross(b, a);       // (0, 0, -1)  순서를 바꾸면 반대
Vector3.Cross(a, a * 3);   // (0, 0, 0)   평행이면 0 벡터
```

내적과 짝을 이룸. 내적은 cosθ, 외적은 sinθ를 담는데, 코사인은 +30도와 −30도가 같은 값이라 어느 쪽으로 틀어졌는지 모르고 사인은 부호로 구분함. 그래서 내적은 앞이냐 뒤냐, 외적은 왼쪽이냐 오른쪽이냐(그리고 회전축)를 알려주고, 둘을 합치면 부호 있는 각도(다음 항목).

좌우 판별. 2D는 z성분만 남아 스칼라 `ax·by − ay·bx`가 되고, 양수면 반시계·음수면 시계 방향. 3D는 외적이 위를 향하는지로 보되, 캐릭터가 기울 수 있으면 월드 y 대신 자기 위쪽 축과 내적해 부호를 뽑음. 부호만 보므로 정규화는 필요 없음.

```csharp
float Cross2D(Vector2 a, Vector2 b) => a.x * b.y - a.y * b.x;
Cross2D(Vector2.right, Vector2.up);     //  1  반시계
Cross2D(Vector2.right, Vector2.down);   // -1  시계

Vector3 to = enemy.position - transform.position;
float side = Vector3.Dot(Vector3.Cross(transform.forward, to), transform.up);
// 유니티: side > 0 오른쪽, side < 0 왼쪽
// 검산: forward (0,0,1), to (1,0,0) → Cross = (0,1,0) → up과 내적 1 → 오른쪽
```

법선과 넓이. 삼각형 두 변을 외적하면 면의 법선과 넓이가 한 번에 나옴. 꼭짓점 순서(감기 방향)를 바꾸면 법선이 뒤집힘. 유니티는 카메라에서 봐서 시계 방향으로 감긴 면이 앞면이고, 그 삼각형에서 이 식의 법선은 카메라 쪽을 향함. 메시를 코드로 만들 때 순서를 거꾸로 넣으면 면이 안 보이는 이유.

```csharp
Vector3 c = Vector3.Cross(B - A, C - A);
Vector3 normal = c.normalized;        // 면에 수직인 방향
float   area   = c.magnitude * 0.5f;  // 평행사변형의 절반 = 삼각형 넓이
```

함정.

- 좌우 부호는 규약에 의존 — 식 자체는 왼손·오른손 좌표계에서 같고 축이 놓인 방향이 다름. 그래서 같은 식이 유니티(왼손)에선 "오른쪽 = 양수"가 되지만 다른 자료에선 해석이 반대일 수 있음. 옮겨올 때 위처럼 한 번 검산
- 정면과 정후방은 둘 다 0 — 사인은 0도와 180도에서 모두 0이라 외적만으로는 바로 앞인지 바로 뒤인지 모름. 앞뒤는 내적으로 따로 확인
- 평행하면 0 벡터 — `Cross(up, forward)`로 오른쪽 축을 만들 때 forward가 정확히 위를 보면 결과가 0이라 기저가 무너짐. 카메라가 정확히 위·아래를 볼 때 회전이 튀는 흔한 원인이라 이 경우를 따로 처리하거나 다른 보조 축을 씀

### 부호 있는 각도(signed angle)

내적은 cos(0~180°, 부호 없음)만 줘 방향을 모름. 외적이 방향(부호)을 줌. `signedAngle = Atan2(cross, dot)`(cross = sin 성분/방향, dot = cos 성분). 2D는 외적 스칼라가 바로 부호, 3D는 기준 축(axis)과의 내적 부호 → `Vector3.SignedAngle(from, to, axis)`.

### 벡터 투영과 벽 슬라이딩 ★

벽 법선 n(정규화)에 대해 미끄러질 속도 = `v − (v·n)·n`. `v·n`이 v 중 법선 방향 성분의 크기(스칼라), `(v·n)·n`이 벽 수직 성분 벡터 → 빼면 벽과 평행한 성분만 남음.

### 경사면 중력 분해

미끄러지는 힘 = `g − (g·n)·n`. 벽 슬라이딩과 정확히 같은 구조로, 수직 성분을 빼면 경사면 평행 성분만 남음. `(g·n)`은 스칼라라 n을 다시 곱해 벡터로 만드는 것 — 끝의 `·n`이 빠지면 안 됨.

### 반사 벡터(reflection)

입사 d, 정규화된 법선 n일 때 `r = d − 2·(d·n)·n`. 내적 `d·n`이 법선 방향 성분의 크기를 뽑아내고, 그걸 두 배로 빼서 법선 성분만 반전(벽과 평행한 성분은 유지). 각도를 구해 다시 만드는 게 아니라 벡터 공식으로 바로 계산한다. 유니티는 `Vector3.Reflect`.

## 회전과 쿼터니언

돌리는 걸 짐벌 락 없이 안정적으로 다루고, 회전 사이를 부드럽게 잇는 도구.

### 짐벌 락과 쿼터니언 ★

오일러 각은 세 축 회전을 순차 적용하는데, 가운데 축이 90°가 되면 첫 축과 셋째 축의 회전축이 겹쳐 자유도 하나를 잃음(3 → 2). 쿼터니언은 (w, x, y, z) 4개 값으로 축-각도를 한 번에 표현해 순차 누적이 없어 짐벌 락이 안 생기고, slerp로 부드럽게 보간되며 합성이 안정적. 쿼터니언은 행렬이 아니며, 비교 대상은 행렬이 아니라 오일러 각이다.

### Lerp vs Slerp ★

Lerp는 직선 보간이라 위치에 적합. Slerp는 원호를 따라 일정한 각속도로 보간해 회전·방향에 적합. 회전을 Lerp하면 각속도가 불균일하고 재정규화가 필요해 부자연스러움.

### Quaternion.Slerp

`Slerp(현재, 목표, speed·dt)`로 매 프레임 조금씩 보간. 구면 선형 보간이라 두 회전 사이를 일정 각속도·최단 호로 부드럽게. 오일러 각을 각각 선형 보간하면 짐벌 락·축 간섭으로 경로가 일그러짐. 작은 각도는 Lerp + 정규화로 근사 가능.

### RotateTowards — 회전 속도 제한

`Quaternion.RotateTowards(현재, 목표, maxDegrees·Time.deltaTime)`로 초당 maxDegrees 이하로만 회전(넘으면 클램프). deltaTime을 곱해 "초당" 일정 각도를 보장(프레임률 무관). Slerp가 "비율 t 보간"이면 RotateTowards는 "초당 고정 각도"라 속도 제한에 맞음.

### 재정규화 — 부동소수점 오차

부동소수점은 실수를 정확히 저장 못 해 회전 행렬/벡터를 오래 곱하면 크기가 1에서 미세하게 벗어남. 회전은 크기를 안 바꿔야 하는데 1.001/0.998로 흐르면 오브젝트가 커지거나 작아지고 계산(내적 = cos)이 틀어짐 → 주기적 재정규화로 단위 길이 유지.

## 보간과 부드러운 이동

목표로 자연스럽게 다가가기. "보간이라 부드럽다"가 아니라 "남은 거리에 비례해 줄어드는 반복"이 핵심이고, 프레임률 의존이 단골 함정.

### Lerp 감속 — 체력바/카메라 ★

`Lerp(current, target, t)`를 매 프레임 current를 갱신하며 반복하면, 매번 남은 거리의 t 비율만큼 줄어 목표에 가까울수록 조금씩 줄어듦 → 감속(ease-out). "보간 함수라서"가 아니라 "남은 거리에 비례해 줄어드는 반복"이 이유. 목표에 정확히 안 닿아 보통 스냅 처리.

### MoveTowards vs Lerp

`MoveTowards(a, b, maxDelta)`는 일정 속도로 목표에 정확히 도달(클램프). Lerp는 쓰는 방식에 따라 달라짐 — `Lerp(start, target, t)`로 t를 0→1 선형으로 올리면 일정 속도·정확 도달이지만, `Lerp(current, target, speed·dt)`는 감속(ease-out)이라 영영 정확히 안 닿음.

### 스무스 팔로우 — 프레임률 의존 ★

`Lerp(현재, 목표, t)`를 매 프레임 반복하면 프레임 횟수만큼 비율을 줄이는 지수 감쇠라, 고프레임이 더 빨리 붙음. deltaTime을 곱하는 건 개선이나 지수 특성 때문에 근사일 뿐 완벽하지 않음. 정확한 프레임률 독립은 `1 − exp(−k·dt)` 사용.

### SmoothDamp — 스프링-댐퍼 추적

`Vector3.SmoothDamp`는 목표를 향해 임계 감쇠 스프링처럼 부드럽게 따라감 — 현재 속도를 상태로 들고 다녀 튐 없이 가감속. Lerp 감속이 프레임률에 흔들리는 것과 달리 목표 도달 시간(smoothTime)으로 지정해 프레임률과 무관하고, 오버슛 없이 자연스럽게 정착. 카메라 추적·UI 이동에 흔히 씀.

### 베지어 곡선

제어점으로 곡선 모양 조종. 3차 베지어는 P0(시작)·P3(끝)·P1·P2(끌어당기는 제어점). 곡선은 제어점 쪽으로 끌리나 닿진 않음. de Casteljau는 Lerp를 중첩하면 곡선이 나오는 방식. 직선 보간과 달리 곡률·자연스러운 가감속·연결(스플라인) 가능.

## 좌표계와 변환

로컬과 월드를 오가고, 손잡이와 곱 순서가 결과를 조용히 뒤집는다.

### 좌표계 — 왼손 vs 오른손 ★

축 방향과 회전의 양(+) 방향을 정하는 규약. 오른손 좌표계는 엄지=x·검지=y·중지=z(OpenGL·수학 관례), 왼손은 z가 반대로 화면 안쪽(유니티·DirectX). 유니티는 왼손·Y-up이라 +z가 전방. 외적의 부호와 회전 방향이 손잡이(handedness)에 따라 뒤집히므로, 다른 엔진·포맷과 데이터를 주고받을 땐 축 변환이 필요.

### 행렬 곱 순서 — TRS ★

행렬 곱은 교환법칙이 성립하지 않아 순서가 결과를 바꿈. 제자리 회전은 회전 후 이동(T·R), 원점 중심 공전은 이동 후 회전(R·T). 문제에 위치 전제가 없으면 "제자리 회전 = 회전만"도 유효.

### TransformPoint / InverseTransformPoint

로컬↔월드 변환. `TransformPoint`(로컬 → 월드)는 캐릭터 기준 총구 위치를 세계 좌표로(스폰·이펙트). `InverseTransformPoint`(월드 → 로컬)는 월드의 적이 내 기준 앞/뒤인지 판단. 내부는 모델 행렬(TRS)/역행렬 곱이라 부모 회전·스케일이 자동 반영. 방향 벡터엔 `TransformDirection`(이동 무시).

## 충돌 판정

겹쳤는지 알아내고 어떻게 튕길지 정하기. 분리축 하나로 AABB부터 볼록 다각형까지 이어지고, 거리 비교는 제곱으로 제곱근을 피한다.

### AABB 충돌 ★

모든 축에서 겹쳐야 충돌. 한 축이라도 분리되면(예: `A.maxX < B.minX`) 그 축에 틈이 있어 충돌이 아님(분리축 정리).

### 분리축 정리(SAT) ★

두 볼록 도형은 어떤 축에 투영했을 때 겹치지 않는 축이 하나라도 있으면 충돌이 아님. AABB는 검사 축이 좌표축뿐이라 간단하고, 회전한 사각형(OBB)·볼록 다각형은 각 변의 법선을 후보 축으로 모두 검사. 하나라도 틈이 있으면 즉시 비충돌로 종료(조기 탈출). 오목 도형엔 직접 못 쓰고 볼록 분해가 필요.

### 원형 충돌과 제곱 거리

두 원은 중심 거리 < r1 + r2이면 충돌. 거리 계산엔 비싼 제곱근이 필요하므로, 양변을 제곱해 거리² < (r1+r2)²로 비교하면 sqrt 없이 같은 판정. 유니티는 `(c1-c2).sqrMagnitude < (r1+r2)²`.

### 점-선분 최단 거리와 캡슐 충돌

점 P에서 선분 AB까지의 최단 거리는 P를 AB에 투영한 파라미터 `t = (P−A)·(B−A) / |B−A|²`를 `[0,1]`로 클램프해 구함 — t가 범위를 벗어나면 가장 가까운 점은 선분의 끝점. 캡슐은 선분(축)을 반지름 r로 부풀린 도형이라, 구-캡슐·캡슐-캡슐 충돌이 전부 "두 축 사이 최단 거리 < 반지름 합"으로 환원됨. 원형 충돌의 선분 버전이고, 제곱 거리로 비교하면 sqrt를 피함.

### 무게중심 좌표(barycentric)

삼각형 내부의 점을 세 꼭짓점의 가중치 `(u, v, w)`로 표현(합이 1). 세 가중치가 모두 0 이상이면 점이 삼각형 안 → 점-삼각형 충돌 판정. 같은 가중치로 꼭짓점의 색·UV·법선을 섞으면 표면 보간이 되고(래스터화가 이 방식), 광선-삼각형 교차와 메시 위 위치 계산에도 쓰임.

### 광선-구 충돌 판별식

광선 `P(t) = O + t·D`를 구 방정식에 대입 → `at² + bt + c = 0`. 판별식 `D = b² − 4ac`가 음수면 빗나감, 0이면 접함(1점), 양수면 관통(2점). t는 거리 파라미터라 충돌점 거리도 나옴. 두 근이 음수면 광선 뒤쪽이라 실제 충돌이 아님(`t ≥ 0`만 유효).

### 충돌 응답 — 반발 계수와 임펄스

충돌을 감지한 뒤 어떻게 튕길지 정하는 단계. 충돌 법선 방향의 상대 속도에 임펄스(순간적 운동량 변화)를 가해 두 물체 속도를 갱신. 반발 계수 e(0~1)가 튐 정도 — 1이면 완전 탄성(운동에너지 보존), 0이면 완전 비탄성(붙어서 같이 이동). 무거운 쪽이 덜 밀리도록 질량 역수에 비례해 임펄스를 배분.

## 물리 적분과 게임 수학

각도·주기 함수, 그리고 매 프레임 속도로 위치를 옮기는 적분. 시간 간격(dt)과 고정 스텝이 재현성을 가른다.

### Atan2 vs Atan

`Atan`은 입력이 비율 dy/dx 하나라 부호 정보가 날아가 정반대 방향을 구분 못 하고(치역이 −90°에서 +90°), dx = 0이면 0 나누기로 터짐. `Atan2`는 dy·dx를 각각 부호까지 받아 4사분면을 모두 구분(치역이 −180°에서 +180°).

### 원형 배치

i번째 위치 = `(r·cos(2πi/N), r·sin(2πi/N))`. 각을 2π/N씩 나눠 같은 간격. 단위원에서 각 θ인 점의 좌표가 정의상 (cos θ, sin θ)이고(= 단위 벡터를 각 축에 투영한 값), r을 곱하면 반지름 r 원.

### sin 부유 애니메이션

`y = baseY + amplitude × sin(Time.time × frequency)`. sin이 부드러운 이유는 단순히 주기적이어서가 아니라(톱니파도 주기적), 곡선이 연속적이고 꼭대기·바닥에서 속도가 0으로 감속했다 가속하기 때문.

### 포물선 — 등가속도 운동 ★

매 프레임 `velocity += gravity·dt`(수직 속도가 일정량씩 감소 = 등가속), `position += velocity·dt`. 수평은 힘이 없어 등속, 수직은 중력이라는 일정 가속도. 변하는 속도로 위치를 옮겨 궤적이 곡선(포물선). 오일러 적분과 동일.

### 세미-임플리싯 오일러 vs 베를레 적분 ★

| | 갱신 | 특징 |
| --- | --- | --- |
| 명시적 오일러 | 옛 속도로 위치 갱신 | 단순하나 에너지가 새어 발산 위험 |
| 세미-임플리싯 오일러 | 속도 먼저 갱신 후 그 속도로 위치 | 안정적, 게임 물리의 기본 |
| 베를레 | 위치·이전 위치로 다음 위치 추정(속도 암묵) | 에너지 보존 좋고 제약 처리 쉬움, 천·로프·파티클 |

세미-임플리싯은 속도를 먼저 갱신해 명시적 오일러의 발산을 억제하고, 베를레는 속도를 직접 안 들고 두 위치의 차로 다뤄 거리 제약을 반복 이완으로 풀기 좋음.

### 드래그와 종단 속도

공기 저항은 속도에 비례(또는 제곱)해 반대로 작용. 매 스텝 `v *= (1 − drag·dt)`로 근사하면 속도가 지수적으로 줄고, 중력 같은 일정 힘과 균형을 이루는 지점에서 더는 안 빨라지는 종단 속도에 수렴. drag가 크면 금세 느려지고, dt가 크면 `(1 − drag·dt)`가 음수가 돼 뒤집히므로 스텝을 작게.

### 고정 timestep — 물리 적분 ★

가변 프레임률로 물리를 적분하면 dt가 들쭉날쭉해 결과가 프레임률마다 달라지고, 큰 dt에선 터널링(빠른 물체가 벽을 통과)이 생김. 유니티는 물리를 고정 간격 FixedUpdate에서 돌려 재현성을 확보하고, 렌더 프레임과 물리 스텝 사이는 보간으로 메움. 렌더는 Update(가변), 물리는 FixedUpdate(고정)로 분리.

### Time.deltaTime ★

직전 프레임에서 지금까지 걸린 시간(초). 속도 × deltaTime = 이번 프레임 이동 거리 → 고프레임은 조금씩 자주, 저프레임은 많이 가끔 움직여 1초 총 이동량이 같아짐. 안 곱하면 "프레임당 고정 거리"라 60fps가 30fps의 2배로 움직임. "프레임률의 역수"가 아니라 "한 프레임의 소요 시간 간격"이 정확한 정의.
